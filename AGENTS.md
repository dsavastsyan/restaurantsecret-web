# AGENTS.md

## Pull request обязателен

Любые изменения в репозитории должны завершаться созданием pull request. Агент не оставляет готовые изменения только в локальной ветке: создаёт отдельную ветку, коммитит относящиеся к задаче файлы, отправляет ветку в remote и открывает PR. Если создать PR технически невозможно (нет доступа, remote или сети), агент явно сообщает конкретную причину и не называет задачу полностью завершённой.

## Режим технических работ

Единственный штатный способ включить экран технических работ на
`restaurantsecret.ru` — изменить `public/maintenance.json` в этом репозитории. Экран
отрисовывает `src/components/MaintenanceScreen.jsx`; агент не создаёт альтернативную
HTML-заглушку в Caddy, nginx, Cloudflare, backend-репозитории или production-конфиге.

### Включение

1. Создать отдельную ветку от актуального `origin/main`.
2. В `public/maintenance.json` установить `enabled: true`, актуальные `from` и `to` в
   ISO 8601 с часовым поясом, а также согласованный пользовательский текст в `message`.
   Не менять дизайн компонента, `title` и `bypassKey`, если задача явно этого не требует.
3. Проверить валидность JSON и просмотреть diff: изменение должно касаться только
   параметров текущего окна технических работ.
4. Создать PR. Режим попадёт на сайт только после merge и завершения штатного deploy
   веб-репозитория; агент не считает его включённым до проверки production.
5. Проверить `https://restaurantsecret.ru/maintenance.json` с cache-busting query и
   публичную страницу в чистой браузерной сессии. Ожидается штатный
   `MaintenanceScreen`, а не текстовая серверная заглушка.

### Выключение

Установить `enabled: false` отдельным PR, дождаться штатного deploy и проверить, что
публичная страница снова открывает приложение. Не оставлять режим включённым только
потому, что указанное в `to` время уже прошло: поле `enabled` является kill switch.

### Если веб-приложение или его static origin недоступны

Не подменять штатный экран самодельным HTML на сервере. Это аварийная ситуация, в
которой нормальный механизм не может загрузиться; агент останавливается и запрашивает у
founder отдельное решение о временном fallback-экране и его точном дизайне. Любой такой
fallback должен быть заранее согласован, воспроизводить штатный экран и иметь явный
план удаления.
